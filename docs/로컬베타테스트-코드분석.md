# 로컬 베타 테스트 코드 분석

- 작성일: 2026-03-22
- 기준: 현재 로컬 코드베이스만 기준으로 점검
- 제외: 베타 참여 후보 명단, 업체 후보 리스트 같은 운영 대상 정보

## 한줄 결론

현재 코드베이스는 `리드 생성 -> 업체 알림 -> 상태 변경 -> 이력 저장 -> 환불/감사로그`까지의 기본 흐름은 갖춰져 있어서 클로즈드 베타를 "제한적으로" 돌릴 수는 있습니다.

다만 베타 계획서 기준으로 보면 아직 `모든 항목이 준비된 상태`는 아닙니다. 특히 `초대 링크 가입`, `관리자 승인 후 활성화 완결`, `실제 SMS 발송`, `리드 열람 시각/미열람 집계`, `응답률/평균 응답시간의 관리자 노출`, `관리자 수동 크레딧 조정`, `관리자 2FA`, `HTTPS 강제`는 비어 있거나 부분구현 상태입니다.

## 항목별 판정

| 항목 | 판정 | 메모 |
| --- | --- | --- |
| 의료인 / 업체 / 관리자 권한 분리 | 구현됨 | `profiles.role`, API 가드, leads RLS로 분리되어 있음 |
| 의료인은 본인 문의만 조회 | 구현됨 | RLS에서 `doctor_user_id = auth.uid()` |
| 업체 간 리드 정보 접근 차단 | 구현됨 | 업체 owner 기준 RLS, 관리자만 전체 조회 |
| 초대 링크 기반 회원가입 | 미구현 | 현재는 공개 `/signup` + `supabase.auth.signUp()` 구조 |
| 관리자 승인 후 활성화 구조 | 부분구현 | 검수 승인 API는 있으나 승인 시 계정/업체 상태를 완결적으로 활성화하지 않음 |
| 리드 생성 시 고유 ID / 생성 시간 / 의료인 매핑 / 문의 저장 | 구현됨 | `leads` 테이블 + 생성 API에서 모두 처리 |
| 업체 자동 문자 발송 | 부분구현 | 실제 구현은 `이메일 + 카카오 알림톡`; SMS 경로는 확인되지 않음 |
| 알림 발송 성공/실패 로그 저장 | 구현됨 | `notification_deliveries` 테이블에 기록 |
| 업체 리드 목록 조회 / 상태 변경 / 상태 이력 저장 | 구현됨 | 상태 변경 API + `lead_status_history` 기록 |
| 리드 열람 시간 기록 | 미구현 | 리드 단위 `viewed_at` 성격의 필드/업데이트가 없음 |
| 72시간 미열람 자동 감지 | 미구현 | 현재 cron은 `미열람`이 아니라 `submitted 상태의 미응답` 기준 |
| 48시간 경고 / 72시간 자동 환불 | 부분구현 | 리드 생성 후 미응답 기준으로 경고/환불 cron 존재 |
| 업체별 응답률 자동 계산 | 부분구현 | 일부 내부 계산은 있으나 관리자 운영 화면/API로 충분히 노출되지 않음 |
| 평균 응답시간 자동 계산 | 부분구현 | 베타 운영 기준으로 바로 쓰는 관리자 지표는 없음 |
| 관리자 전체 리드 조회 | 부분구현 | 통계 페이지와 CSV export는 있으나 전용 전체 리드 리스트 화면/API는 못 찾음 |
| 관리자 업체별 리드 수 통계 | 부분구현 | 총량/상태 통계는 있으나 베타 운영용 업체별 SLA 지표는 부족 |
| 관리자 알림 발송 로그 조회 | 부분구현 | DB 저장은 되지만 관리자용 조회 UI/API는 확인하지 못함 |
| 관리자 리드 상태 변경 로그 조회 | 부분구현 | `lead_status_history` 저장은 있으나 관리자용 운영 UI/API는 부족 |
| 크레딧 지급/차감 수동 조정 | 미구현 | `admin_adjust` 타입과 RPC는 보이지만 관리자 UI/API는 못 찾음 |
| 비밀번호 암호화 저장 | 간접 충족 | 앱 DB가 아니라 Supabase Auth에 위임 |
| HTTPS 적용 | 코드 기준 미구현 | 강제 redirect/HSTS middleware나 header 설정이 없음 |
| DB 외부 접근 차단 | 코드만으로 확인 불가 | 클라이언트 직접 DB CRUD는 거의 안 보이지만 인프라 차단 여부는 저장소만으로 판단 불가 |
| 관리자 2단계 인증 | 미구현 | Supabase local config에서도 MFA 비활성 |
| 서버 로그 저장 | 부분구현 | `audit_logs`, `notification_deliveries`, `Sentry`는 있으나 중앙 운영 로그 체계는 아님 |

## 지금 당장 중요한 부족 항목

### 1. "리드 생성됐는데 업체 문자 미수신"을 코드가 막아주지 못함

- 리드 생성 후 업체 알림은 `best-effort`라서 실패해도 리드 생성 자체는 성공으로 끝납니다.
- 구현 채널도 SMS가 아니라 `이메일 + 카카오 알림톡`입니다.
- 게다가 현재 리드 생성 API는 `ownerProfile.email`이 있을 때만 알림 발송 블록을 타므로, 이메일이 없고 전화번호만 있는 업체는 알림이 아예 건너뛰어질 수 있습니다.

즉, 계획서의 `절대 발생하면 안 되는 오류` 중 하나인 `리드 생성됐는데 업체 문자 미수신`은 현재 구조상 충분히 발생 가능합니다.

### 2. "미열람" 운영 기준을 지금은 계산할 수 없음

- 계획서에는 `24시간 이상 미열람`, `72시간 미열람 유도`, `미열람 리드 수`가 중요한 운영 지표로 잡혀 있습니다.
- 그런데 현재 코드에는 리드 자체의 열람 시각을 기록하는 로직이 없습니다.
- 그래서 지금 있는 cron은 `읽지 않음`이 아니라 `submitted 상태로 남아 있음`만 기준으로 동작합니다.

즉, 베타 체크리스트의 핵심 운영 지표 중 일부는 현재 코드만으로는 측정이 안 됩니다.

### 3. 관리자 운영 화면이 베타 운영 기준으로는 아직 부족함

- 현재 관리자 쪽은 `리드 총량/전환율 통계`, `감사 로그`, `환불 심사`, `CSV export`는 있습니다.
- 하지만 베타 운영에 바로 필요한 `업체별 응답률`, `평균 응답시간`, `24시간 이상 미열람 리드 수`, `알림 발송 실패 로그`, `전체 리드 운영 리스트`는 충분히 보이지 않습니다.

즉, 데이터는 일부 쌓여도 운영자가 매일 체크리스트대로 관리하기엔 화면/API가 아직 부족합니다.

### 4. 보안 필수 항목은 아직 "운영 준비 완료"로 보기 어려움

- 비밀번호 자체는 Supabase Auth에 맡겨서 평문 저장은 하지 않습니다.
- 하지만 `관리자 2FA`는 없고, `HTTPS 강제`도 코드상 확인되지 않았습니다.
- `DB 외부 접근 차단`은 저장소가 아니라 Supabase/Vercel 운영 설정 영역이라 별도 확인이 필요합니다.

## 폐쇄 베타 가능 여부 판단

### 가능한 범위

- 승인된 의료인이 리드를 생성하고
- 승인된 업체가 자기 리드를 조회하고 상태를 바꾸고
- 상태 이력이 남고
- 과금/무응답 환불/감사로그가 기본적으로 남는 수준의 베타는 가능합니다

### 그대로 시작하면 위험한 부분

- 알림 실패가 리드 생성 성공과 분리되어 있어 운영자가 놓칠 수 있음
- "미열람" 기준 운영이 불가능함
- 관리자용 일일 운영 대시보드가 체크리스트 수준까지는 안 올라와 있음
- 보안 필수 항목 중 일부가 아직 미구현/운영 미확인 상태임

## 베타 시작 전 우선순위 제안

1. 리드 알림을 `필수 성공` 또는 `명확한 재시도/실패 대기열` 구조로 보강
2. 리드 `열람 시각(viewed_at)`과 `미열람 집계` 추가
3. 관리자 운영 화면에 `업체별 응답률`, `평균 응답시간`, `미열람 리드 수`, `알림 실패 로그` 추가
4. 관리자 `수동 크레딧 지급/차감` API/UI 추가
5. `초대 링크 가입 + 관리자 승인 후 활성화` 흐름 정리
6. `관리자 2FA`, `HTTPS 강제`, 운영 환경의 DB 접근 정책 확인

## 최종 판단

현재 코드는 `베타용 핵심 플로우의 뼈대는 있음`이 맞습니다.

하지만 계획서에서 기대하는 수준으로 보면 `전부 구현 완료`는 아니고, 실제로는 `핵심 기능은 일부 가능 / 운영 기능과 보안 항목은 여러 개 부족` 상태입니다. 특히 운영에서 가장 아픈 빈칸은 `알림 보장`, `미열람 추적`, `운영 대시보드`, `수동 크레딧 조정`, `2FA/HTTPS`입니다.
